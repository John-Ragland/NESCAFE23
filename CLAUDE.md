# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

NESCAFE23 is the analysis and research codebase for the 2023 pilot New England Seamounts Calibrated Acoustic Fluctuation Experiment (NESCAFE23). It is a `uv` workspace containing:

- **`src/nescafe23/`** — the main shared library (data I/O, physics utilities, CLI, visualization)
- **`packages/acoustic_inversion/`** — tools for ray-based underwater acoustic inversions (MAP updates, Jacobians, forward models via `pygenray`)
- **`packages/nesma_param/`** — parameterization of NESMA-region oceanography (Argo-based models, JAX helpers)
- **`projects/n23_inversion_ragland/`** — simultaneous source localization and ocean acoustic inversion
- **`projects/n23_fluctuations_ragland/`** — acoustic fluctuation analysis
- **`projects/n23_source_localization_hoekstra/`** — source localization (Hoekstra)

All packages/projects are managed as a single `uv` workspace defined at the root.

## Commands

**Install everything (editable, workspace-wide):**
```bash
uv sync
```

**Run tests (workspace root or within a package/project):**
```bash
uv run pytest
# single test:
uv run pytest tests/test_foo.py::test_bar
```

**Lint (within a package or project that has a noxfile):**
```bash
uv run noxfile.py -s lint     # ruff via prek (pre-commit) on all files
uv run noxfile.py -s pylint   # pylint
```

**Build docs:**
```bash
uv run noxfile.py -s docs
```

**Run the CLI:**
```bash
uv run nescafe23
```
The CLI is interactive (uses `questionary`) and handles: setting `NESCAFE23_DATADIR`, computing arrival time offsets, and estimating peak locations.

## Data directory

All data access goes through `nescafe23.get_data_dir()`, which reads `NESCAFE23_DATADIR` from a `.env` file at the workspace root (or the environment). Running `nescafe23` in the terminal will prompt to set it if missing.

Expected data structure under `NESCAFE23_DATADIR`:
- `dmod/dm*.mat` — demodulated reception files (HDF5/MAT format)
- `environment_data/FCTD_SoundSpeed_Colosi_v2.mat` — fast CTD data
- `dataproducts/T_t_estimated.pkl` — tidal arrival time offsets (generated by CLI)
- `dataproducts/peak_locations.pkl` — estimated peak arrival locations (generated by CLI)

## Architecture

### Data flow
Raw `.mat` files → `convert_to_xarray()` → xarray Datasets with `hydrophone`, `time` dims and `dmod` (complex128) variable → tidal-shift-corrected receptions via `open_receptions()` → peak location estimation → inversion.

### Key dependencies
- **`pygenray`** — ray tracing (installed from GitHub, not PyPI); used in `acoustic_inversion` for `pr.shoot_rays`, `pr.find_eigs`, `pr.OceanEnvironment2D`
- **`xrsignal`** — xarray-native signal processing (Butterworth filter application via `xrs.filtfilt`)
- **`jax` / `equinox`** — used in `nesma_param` for differentiable ocean models
- **`gsw`** — TEOS-10 seawater thermodynamics

### `acoustic_inversion` package
The core inversion logic lives in `packages/acoustic_inversion/src/acoustic_inversion/acoustic_inversion.py`. Key functions:
- `ray_forward` / `ray_forward2` — run ray tracing and return eigenrays
- `ray_jacobian` / `ray_jacobian_sl` — finite-difference Jacobians w.r.t. environment or source position
- `MAP_update` — linear MAP (maximum a posteriori) update step
- `quadratic_approximation` — Laplace/quadratic posterior approximation

### `nesma_param` package
Provides ocean environment parameterization using Argo float climatology and JAX-based generative models. Exposes `gen_models`, `open_data`, and `jax_helpers`.

### Typing and linting
- All packages use `src/` layout with `py.typed` markers (fully typed)
- mypy strict mode on `src/` code; relaxed for tests
- ruff with an extensive rule set (see any `pyproject.toml`); `T20` (print) ignored in tests/noxfile
- `PLR09` (too many args/branches) and `PLR2004` (magic values) are globally ignored
